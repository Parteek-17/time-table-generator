## Done

- M1: `@slotwise/shared/portal` — date helpers (`localNow`, `weekStartOf`, …), calendar
  scoping (`scopeCovers`, `holidayFor`, `runsWeekday`: institute / department / programme /
  cohort / section holidays and extra working days), `buildToday()` (portal-read.v1) and
  `buildWeek()` (`PortalWeekV1`, P5-internal). A student's class is off when their own section
  is on holiday; a teacher's class only when every section attending is. Students see only the
  electives they chose (all of them when none are recorded).
- API `GET /portal/today[?date=]` (portal-read.v1) and `GET /portal/week[?date=]` behind
  `@FeatureFlag('P5')`, `timetable.view`. Who is looking comes from the sign-in only: a teacher
  by `Faculty.userId`, a student by `Student.email` (case-insensitive, active). Their week is
  read through P2T's `GET /terms/:termId/timetable` over HTTP as the viewer (never P2T's
  tables); the calendar (term, holidays, extra working days, bell-schedule working days,
  section places) is read from P1's tables under RLS. Not linked → 404 with a plain message.
- Web `(portal)` group: light layout (no admin nav, no client JS except the error boundary),
  `/today` (next / happening-now class, the day's classes with cancelled ones struck through
  and labelled in words, changes in the next 7 days, exam-seat placeholder, previous / next
  day) and `/week` (day by day, holidays, link from each day to its Today, previous / next
  week). Today ↔ Week tabs with `aria-current`, 44 px targets, loading skeleton, error retry.
  Nav group "My timetable" (`p5.ts`) for `timetable.view`. Strings in `messages/en/p5.json`.
- Seed `p5.ts`: student login `student@demo.slotwise.test` (Demo Student, roll DEMO-S001,
  CS B). Teacher login: P1's `faculty@demo.slotwise.test` (KN).
- Playwright `e2e/p5/portal.spec.ts` written, **not run** (needs dev servers; not started on
  this machine per the memory limit).
