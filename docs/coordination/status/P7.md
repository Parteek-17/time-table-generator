## Done

- ADR 0090 (sign-up, platform admins via `can()`, plans and limits).
- `@slotwise/shared/platform`: `PLANS` (trial 30 days: 3 departments / 12 sections / 60 faculty
  / 800 students; college 15 / 120 / 400 / 6000; university unlimited), `checkLimit()`,
  `usageReport()` (nearly full from 80%), trial dates as `YYYY-MM-DD`; zod `signupSchema`
  (honeypot, lower-cased slug and email), `setPlanSchema`; `suggestSlug()`; DTOs.
- `platform.prisma`: `InstituteSubscription` (one per institute; plan code, last trial day) +
  back-relation on `Institute`.
- API (all behind `@FeatureFlag('P7')`):
  - `POST /signup` (public): provisioning with `actorUserId: null`, trial plan; invite email is
    the address check. Limits: 3 per email per day, 60 per hour (in-memory). `GET /signup/slug`.
  - `GET /platform/institutes` (search, 50 newest, with plan), `PUT /platform/institutes/:id/plan`
    (audited `billing.plan_changed`), both `PlatformAdminGuard`.
  - `GET /billing/plan`: plan, trial days left, usage per limit (institute admins).
  - `institute.created` listener: every new institute gets the trial (idempotent upsert).
  - `BillingService.assertCanAdd(tx, instituteId, kind, adding)`: 403 `plan_limit` in plain words.
- Web: `/welcome` marketing page (features, how it works, plans from `PLANS`), `/signup` form
  (address suggested from the name, live "is it free", plain errors), `/platform` (institutes,
  search, change plan) and `/platform/institutes/new` (calls `POST /platform/institutes`, then
  sets a non-default plan). Strings in `messages/en/p7.json`.
